# Capacitor iOS — Finish (Simulator-Ready) Design Spec

**Date:** 2026-08-23
**Status:** Approved (scope: "Simulator-ready")
**Builds on:** the Capacitor 8 spike on branch `spike/capacitor-ios` (proof done) and the current `main` (all UI/responsive work).

## Overview

Take the proven Capacitor 8 spike and finish it to the point where the existing React/Vite app **builds and runs in the iOS Simulator against the production Railway backend**, on a clean branch off the current `main`. The spike predates all recent UI work, so we do NOT merge it — we bring its Capacitor pieces (deps + `capacitor.config.json`) forward onto `main` and regenerate the native `web/ios/` project fresh from the current build. Everything that requires the $99 Apple Developer account (physical device, App Store, Apple Sign-In) is out of scope for this pass.

## Program Context

Item 2 of the roadmap ([[project-roadmap]]), after the now-shipped responsive work. Approach (wrap the web app with Capacitor 8, no rewrite) was decided and spiked earlier ([[project-capacitor-ios]]). This spec finishes it to simulator-ready.

## Key Facts (verified)

- **Prod frontend→backend:** CI builds with `VITE_API_URL` = the absolute Railway URL (GitHub secret). Firebase Hosting only serves the SPA (`rewrites: ** → /index.html`) — there is **no** same-origin API proxy. Backend URL: `https://precious-acceptance-production.up.railway.app`.
- **Capacitor loads the app from `capacitor://localhost`**, so relative `/scan/...` calls would hit the webview, not the API. The native build therefore MUST bake in the absolute Railway `VITE_API_URL`.
- **CORS** (`server/index.js` `allowedOrigins`) currently allows `https://ingredientscan.app`, `https://scanner.joelrog.com`, `http://localhost:5173` — NOT `capacitor://localhost`. Native API calls are blocked until it's added.
- **Toolchain:** Capacitor CLI 8 requires **Node ≥ 22** (`~/.nvm/versions/node/v22.23.2`). `npm install` needs `--legacy-peer-deps` (pre-existing zxing peer mismatch). Spike config: `appId app.ingredientscan`, `appName IngredientScan`, `webDir dist`.
- **The iOS Simulator has no camera** — live barcode/menu scanning cannot be exercised there. This pass verifies load / navigation / auth / backend round-trips only.

## Design Decisions

| Question | Decision |
|----------|----------|
| Branch | New `feature/capacitor-ios` off `main`. Do NOT merge the stale spike branch. |
| Bring-forward | Recreate `web/capacitor.config.json` + add `@capacitor/core`+`@capacitor/ios` (deps) and `@capacitor/cli` (devDep) at `^8.5.0`; `npm install --legacy-peer-deps`; regenerate `web/ios/` via `npx cap add ios` from the current build. |
| Native API URL | New npm script `build:ios` → `VITE_API_URL=https://precious-acceptance-production.up.railway.app vite build && cap sync ios`. Run under Node 22. |
| CORS | Add `capacitor://localhost` to `allowedOrigins` in `server/index.js` (additive; deploys to Railway on merge). |
| Camera permission | Add `NSCameraUsageDescription` to `web/ios/App/App/Info.plist` (needed for getUserMedia even though the simulator can't fulfill it). |
| gitignore | Root `.gitignore` line `ios/` also hides `web/ios/`; add `!web/ios/` so the native project tracks. |
| Out of scope | Apple Developer account, physical device, App Store, Apple Sign-In, native Camera plugin, app icon/splash polish. |

## Architecture / Files

- **`web/capacitor.config.json`** (create) — `{ appId, appName, webDir: "dist" }`.
- **`web/package.json`** (modify) — Capacitor deps + `build:ios` script.
- **`web/ios/`** (generated by `cap add ios`) — the Xcode project; tracked.
- **`web/ios/App/App/Info.plist`** (modify) — camera usage string.
- **`server/index.js`** (modify) — one line in `allowedOrigins`.
- **`.gitignore`** (modify) — `!web/ios/`.

## Testing / Verification

- **Build:** `npm run build:ios` completes under Node 22 (`vite build` clean + `cap sync ios` copies `dist` into the iOS project, no errors).
- **CORS unit:** existing server tests still pass (`node --test`); add a targeted assertion that `capacitor://localhost` is allowed and a random origin is rejected (if a CORS helper is testable; otherwise verify by code review since CORS is inline middleware).
- **Simulator (manual, user-driven; needs the runtime Software Update):** `npx cap open ios` → Run → app loads, Google login works, Home/History/Lists/Profiles render, and a history rematch round-trip succeeds against prod (proving CORS + API URL). Camera scan is expected to be unavailable in the simulator.

## User-Side Blockers (cannot be done by the agent)

1. **CoreSimulator runtime Software Update** — required to launch the simulator.
2. **Apple Developer account ($99/yr)** — required later for device/App Store/Apple Sign-In; not needed for the simulator.

## Out of Scope (later)

- Apple Sign-In ([[feature-backlog]] 3b), device/App Store signing, native Camera/Push plugins, app icon + splash + status-bar theming, Android platform.
